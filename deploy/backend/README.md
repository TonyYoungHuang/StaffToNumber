# Persistent API and worker deployment

Use an x86_64 Ubuntu VPS with at least 4 CPU cores, 8 GB RAM, and persistent SSD storage. Basic Pitch, Audiveris, and ClamAV are long-running workloads and must not run in Vercel functions.

1. Point `api.scoretransposer.com` to the server.
2. Install Docker Engine and the Compose plugin.
3. Copy `.env.production.example` to `.env.production` and set secrets.
4. Run `docker compose --env-file .env.production up -d --build` in this directory.
5. Verify `https://api.scoretransposer.com/health`, authenticated `/metrics`, and `docker compose ps`.
6. Back up the `score_data` volume for SQLite and temporary engine workspaces, and enable versioning plus lifecycle protection on the private S3 bucket.

Production requires `STORAGE_BACKEND=s3`, `S3_BUCKET`, and `S3_REGION`. Use an IAM role or workload identity where available; configure the static key pair only for S3-compatible providers that require it. Objects remain private and use tenant/file-scoped keys, SHA-256 metadata, authenticated API streaming, and checksum-verified Worker materialization. Set `S3_SERVER_SIDE_ENCRYPTION=AES256` for AWS SSE-S3 or `aws:kms` plus `S3_KMS_KEY_ID`; leave the request option empty only when the bucket/provider enforces encryption at rest itself. `S3_ENDPOINT` and `S3_FORCE_PATH_STYLE=true` support MinIO and compatible services.

Before switching an existing installation, run `npm run storage:migrate -w @score/api -- --dry-run`, inspect the JSON report, then run the migration without `--dry-run`. Keep local files for the first restore window; add `--delete-local` only after object counts, sizes, checksums, API downloads, and Worker imports have been sampled successfully. The migration uses per-file claims and records local paths, object keys, sizes, and checksums for rollback evidence. Account and orphan cleanup enqueue object deletion in a persistent outbox with stale-lock recovery and exponential retry.

The SQLite-to-PostgreSQL migration command is a maintenance tool, not the runtime cutover. Freeze API/Worker/Collaboration writes before migrating the live database, or use SQLite's official online backup API to create a consistent source copy; never copy only the `.sqlite` file while WAL activity may be present. Set `POSTGRES_URL`, `POSTGRES_TARGET_SCHEMA`, `POSTGRES_MIGRATION_REPORT`, and an appropriate `POSTGRES_SQLITE_BUSY_TIMEOUT_MS`, then run `npm run postgres:migrate -w @score/api`. Existing target schemas are rejected by default. A replacement requires both `POSTGRES_REPLACE_SCHEMA=true` and `POSTGRES_CONFIRM_REPLACE` equal to the exact schema name. Inspect every per-table row count and checksum in the report before proceeding. To remove only the migrated candidate schema, set `POSTGRES_ROLLBACK_CONFIRM` to that exact schema name and run `npm run postgres:rollback -w @score/api`; the command writes its own table/row removal report. Never point these commands at `public` or a shared application schema.

After migration, set `POSTGRES_PARITY_REPORT` and run `npm run postgres:verify -w @score/api` against the same consistent SQLite source and target schema. The verifier uses SQLite and PostgreSQL repeatable-read snapshots plus a shared advisory lock, writes per-table row/checksum evidence, and exits non-zero for missing/extra tables, incompatible columns, or data drift. A green parity report is mandatory evidence, but it does not enable PostgreSQL as the runtime primary while repository cutover is incomplete.

Redis provides both the shared fail-closed rate-limit store and BullMQ transport, and is not exposed outside the Compose network. The Compose service uses AOF with one-second fsync, `noeviction`, and the `redis_data` volume; back up and restore-test that volume, and monitor AOF fsync latency, memory headroom, queue age, failed jobs, outbox retries, and stalled jobs. Database outbox rows remain the recoverable dispatch source if a publish fails. ClamAV runs as an isolated daemon on TCP 3310; uploaded files remain in `.quarantine` until its INSTREAM response is clean. The `clamav_db` volume preserves signature updates. Before release, verify Redis startup failure blocks production API/Worker startup, run an EICAR upload test, and alert on broker, `rate-limit-store`, ClamAV, 5xx, latency, and audit-write failures.

Audio-transcription and student-performance uploads are inspected with `ffprobe` while still quarantined. The API rejects missing audio streams, unverifiable or excessive duration, oversized video dimensions, and invalid stream layouts. It then runs a metadata-stripping, first-stream-only `ffmpeg` transcode and scans the sanitized output again before promotion. Production must set `MEDIA_SAFETY_REQUIRED=true`, `FFMPEG_COMMAND`, and `FFPROBE_COMMAND`; keep the duration and resolution limits aligned with product entitlements and reverse-proxy upload limits.

Security audit events are append-only application records retained for `SECURITY_AUDIT_RETENTION_DAYS`. Query them through the admin security API. Metrics require `METRICS_BEARER_TOKEN`; never expose that token through the public frontend or Caddy configuration.

API requests return `x-request-id`, `x-trace-id`, and W3C `traceparent`. New legacy and score jobs persist the request and trace IDs, the transactional outbox forwards them to BullMQ, and the Worker includes them in heartbeat details and structured lifecycle logs. Collaboration updates receive a per-authenticated-connection request/trace pair. Keep these identifiers in incident tickets and use them to join API audit events, job rows, Worker logs, and collaboration audits. This is durable application-level correlation; it does not replace exporting spans to a production OpenTelemetry collector.

For staging and production observability, use the private Compose overlay in `../observability` after the base backend stack is healthy. It deploys Prometheus, Alertmanager, Grafana, Loki, and Grafana Alloy with Docker secrets for the metrics token, alert webhook, and Grafana password. Follow `../observability/README.md` and `../../docs/operations/on-call-runbook.md`; do not expose its local Grafana port directly to the internet or mark the release ready until the alert delivery drill succeeds.

Account deletion requires password verification and enters a configurable grace period. Production lifecycle cleanup removes due accounts, revokes active workflows, deletes owned score/classroom rows in foreign-key order, de-identifies retained payment audit records, and sends file deletion through the durable storage outbox. It also prunes expired unreferenced file rows and stale local quarantine files. Keep `LIFECYCLE_CLEANUP_ENABLED=true` in production and false in local development; alert on pending/failed storage deletions and rehearse export, cancellation, final deletion, backup restore, and legal-hold exceptions before release.

Copyright complaints use a dedicated legal workflow rather than ordinary support tickets. The public API returns a reference plus one-time access code and stores only its SHA-256 hash. Operators must use `/admin/copyright`; public claimant messages and internal notes are separate event fields. Configure `SUPPORT_EMAIL` and `COPYRIGHT_RESPONSE_HOURS`, verify transactional email delivery, and rehearse intake, information requests, action, rejection, closure, reopening, counter-notice, and legal-hold handling before release. Do not place complaint access codes in URLs, logs, chat transcripts, or analytics.

Classroom email announcements use the shared Resend credentials but are sent asynchronously by the worker from `score_notification_deliveries`. Configure a verified `EMAIL_FROM_ADDRESS`, `RESEND_API_KEY`, `EMAIL_REPLY_TO`, and `PUBLIC_APP_URL`. Alert on queued age, failed delivery count, and provider rate limits; verify opt-in, opt-out, scheduled publication, cancellation, retry, and idempotent resend behavior before enabling the channel in production.

Score exports are persistent `render_export` jobs. MusicXML and MIDI render inside the worker; PDF/SVG/PNG require MuseScore; WAV/MP3 require FluidSynth, a commercially licensed SoundFont, and ffmpeg. Completed assets record their source revision, render parameters, engine versions, SHA-256 checksum, and stale status. The bundled FluidR3 GM path is suitable for local smoke tests only; verify the chosen SoundFont license before commercial release.

Before staging, copy `soundfont-license-manifest.example.json` to the private `secrets/soundfont-license-manifest.json`, replace every placeholder, and run `MUSIC_ENGINE_QUALIFICATION_REQUIRED=true npm run qualify:music-engines`. Compose mounts that file read-only at the configured `/run/secrets/soundfont-license-manifest.json` path for API and Worker. The command starts every configured notation/audio engine without a shell, records bounded version diagnostics, validates the reviewed SoundFont SHA-256 and commercial-use approval, and writes `artifacts/music-engine-qualification.json`. A missing command, timeout, non-zero exit, unchecked license, or changed SoundFont hash blocks a required qualification run.

The API remains a single replica while SQLite is in use. S3 removes the persistent asset-volume dependency and BullMQ removes active queue scanning in production, but API and Worker must still share the SQLite volume until business repositories move to PostgreSQL. Do not use separate hosts or increase API replicas before that cutover and its recovery rehearsal.
