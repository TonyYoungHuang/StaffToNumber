# 首页前端性能预算

更新日期：2026-08-19

## 目的

P1 首页增加意图切换、案例证据、真实播放和能力边界后，仍要保持轻量。预算检查针对用户首次访问首页必须下载的 JavaScript、CSS，以及产品案例图库的原始资源体积；它不是 Lighthouse 分数的替代品。

## 当前硬预算

| 项目 | 上限 | 约束理由 |
| --- | ---: | --- |
| 首页首次 JavaScript（gzip） | 110 KiB | 保留轻量交互空间，避免把完整编辑器或音频引擎塞进营销首页 |
| 首页 CSS（gzip） | 42 KiB | 允许完整浅色设计系统与响应式规则，同时限制无效样式增长 |
| `public/product` 图片总量 | 1.5 MiB | 案例可以增多，但必须继续使用经过压缩的真实界面证据 |
| 单张产品图片 | 300 KiB | 防止未压缩截图直接进入线上资源库 |

## 运行方式

```powershell
npm --workspace @score/www run build
npm --workspace @score/www run budget:homepage
```

检查脚本读取 Next.js 生产构建生成的首页清单，合并首页与根布局实际引用的资源并去重，然后计算原始与 gzip 体积。缺少生产构建时会明确失败，不使用开发构建冒充结果。

## 运行时原则

- 首屏乐谱截图使用 `next/image`，并仅将主视觉图片标为高优先级。
- 长页面案例图片默认延迟加载；每张图片提供真实宽高，避免布局跳动。
- 播放演示的 `<audio>` 使用 `preload="none"`，用户操作后才获取 WAV。
- 首页只呈现四音符、3.2 秒的自制验证样本；复杂编辑能力继续留在工作区路由。
- 新增第三方脚本、动画库、字体字重或大图前，先重新运行预算检查。

## 非硬编码验收

每次重要首页改版还要在 390、768、1024、1280 像素宽度完成浏览器检查，确认无横向溢出、布局跳动和不可操作控件。发布前再用真实部署执行 Core Web Vitals/Lighthouse；网络与服务器指标不应被本地资源预算替代。
