## 结论

截至 2026-08-21 的定向修复，H1、M1、M2、M3、M4、M5、M6、M7 已完成代码修复并通过对应的静态检查、构建、单元测试和 H1 视觉回归。

## 高优先级问题

### H1. 固定导航栏覆盖 VexFlow 乐谱页（已修复）

影响：核心编辑/校对场景中，SATB 乐谱第一页顶部被导航栏遮住，高音谱表、谱号与音符无法完整查看。

复现：

1. 打开 SATB 四声部候选谱。
2. 进入 VexFlow 图形编辑/校对视图。
3. 查看第一页顶部。
4. 固定导航栏叠在乐谱画布之上。

原始回归结果：期望画布为 710×1005，实际为 848×1200；视觉快照用例失败。失败位置为 `tests/e2e/omr-candidate-review.spec.ts:679`。修复后实际尺寸恢复为 710×1005，同一用例通过。

证据：

- 基准图：`tests/e2e/omr-candidate-review.spec.ts-snapshots/vexflow-satb-page-chromium-win32.png`
- 实际图：`test-results/omr-candidate-review-OMR-c-59298-Flow-engraving-pixel-stable-chromium/vexflow-satb-page-actual.png`
- 差异图：`test-results/omr-candidate-review-OMR-c-59298-Flow-engraving-pixel-stable-chromium/vexflow-satb-page-diff.png`

修复：调整编辑器双栏宽度并增加固定顶栏滚动避让，没有修改视觉基准图。

### H2. 升级入口已展示，但真实在线支付不可完成（投产后开通 Paddle）

原始影响：用户可以进入结算页、选择 4 个套餐、个人/机构订阅及 Stripe/Paddle，但两个渠道均显示“正在建设/等待正式商户验收”，最终按钮只会通知站长，不会扣款或自动开通。

风险：如果生产环境继续展示“升级套餐/在线支付”，用户会认为可以立即购买，实际却无法完成闭环。

处理安排：当前继续关闭公开在线支付入口；部署投产后人工开通 Paddle，再验收真实交易、Webhook、权益发放、取消和退款。

## 中优先级问题

### M1. 中文界面混入英文错误和运行状态（已修复）

已复现的英文内容包括：

- `Password must be at least 8 characters.`
- `Invalid email or password.`
- `The uploaded file content does not match a supported file type.`
- `Activation code not found.`
- `An active entitlement is required.`
- Audiveris/OSMD 原始诊断和系统运行状态。

建议：统一用错误码映射中英文文案；原始引擎信息放入“技术详情”，主提示提供用户下一步。

### M2. 免费额度用完后的上传页缺少解释（已修复）

免费单页识别使用后，再进入扫描页仍会看到完整上传器。选择文件后“开始识别”只变为禁用，没有说明额度已用完、为什么不能点、如何继续。

建议：进入页面即展示“免费次数已用完”，隐藏或锁定上传器，并提供明确升级按钮。

### M3. 免费候选失败状态不够可理解（已修复）

真实免费 PDF 已进入 Worker 并由 Audiveris 完成，但测试谱生成的候选无法由 OSMD 加载，页面只显示 `given music sheet was incomplete or could not be loaded.`，控制台同时出现 `MusicSheetReader.CreateMusicSheet` 错误。

建议：把它转成中文可操作状态，例如“识别结果不完整，请换一页更清晰的乐谱或联系支持”，并提供重新上传/查看诊断入口。

### M4. 未付费用户看到互相矛盾的额度和能力描述（已修复）

- 控制台显示“当前已登录，可以继续上传文件或创建任务”，但任务页和付费导入会跳结算。
- 账单页对未激活账户显示 `LEGACY 套餐配额 1 / 25`，与公开 Pro 100 / Studio 500 积分及“未激活”状态不一致，容易误以为还有 24 次可用。

建议：未激活账户只显示免费试用口径；隐藏历史套餐配额，并让控制台文案与真实权限一致。

### M5. 课堂页对未付费用户展示大量不可用表单（已修复）

后端保护正确，创建机构、课堂、资源、通知和 LMS 等按钮均禁用；但页面仍渲染整套表单，并重复显示英文 `An active entitlement is required.`。同页还出现两个 `h1`。

建议：用一个简洁权限占位页替代所有禁用表单，说明套餐要求和可用能力；修正标题层级。

### M6. 部分公开文案像内部 PRD，而不是面向用户（已修复）

例如 Support 页标题和正文直接讨论“如果你还没有接入更重的客服系统”“商用站点最容易失信的地方”，是在对站长说话。英文首页页脚还出现 `workspace workspace` 重复词。

建议：把公开页面改成直接回答用户“我能做什么、需要提供什么、多久有回应”；内部运营说明移到后台文档。

### M7. 公开站与产品端视觉系统未完全统一（已修复）

公开站使用 Geist/Noto Sans SC 与 `rgb(248,249,253)`，产品端使用 Segoe UI/Microsoft YaHei 与 `rgb(247,248,252)`；产品端页脚品牌为 `The Digital Score`，公开站为 `ScoreTransposer`。

建议：统一字体 token、背景 token、品牌名、页脚与按钮状态；目前布局语言相近，但还不是同一套完整设计系统。

## 配置与本地验收风险

初始已有构建把公开 CTA、产品端 API 和站点地址固化到了生产域名。若直接启动该构建，本地登录会请求线上 API。重新以隔离 URL 构建后功能恢复正常。

另外，本地 `127.0.0.1` 的语言/CTA 跳转会切换到 `localhost`，导致本地 Cookie 域分离，并丢失原本的 `next=/scores#omr-import` 显式路径。生产域名配置正确时不一定复现，但本地 README/启动脚本应强制统一 host 和 URL 环境变量。
