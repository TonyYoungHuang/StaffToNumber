# ScoreTransposer 前端参考站学习基准与差距清单

> 文档性质：长期维护的设计基准、差距台账与验收清单
> 初始版本：2026-08-18
> 参考站：[ChatPPT](https://chatppt.com/)、[BeatViz](https://beatviz.ai/)、[MiniMax H3](https://minimaxh3.art/zh)
> 当前产品：ScoreTransposer 官网与产品工作区
> 维护原则：参考信息架构、交互方法和视觉品质，不复制品牌资产、文案、插图、视频或受版权保护的具体设计

## 1. 文档目的

这份文档把三个参考站的前端设计拆解为可复用、可比较、可验收的条目，并建立 ScoreTransposer 的当前差距台账。后续每一次前端设计或实现工作，都应从本文件选择条目、记录改动证据，并在完成后更新状态。

它要解决四个问题：

1. 三个参考站具体做对了什么，而不是只留下“看起来高级”的模糊印象。
2. 这些优点如何翻译成五线谱、简谱、识谱、移调、播放与导出产品的界面。
3. ScoreTransposer 当前已经具备什么、只做了一部分什么、完全缺少什么。
4. 后续如何逐项比对并证明某一项已经达到目标，而不是凭主观感觉宣布完成。

## 2. 使用方法

### 2.1 状态定义

| 状态 | 含义 |
| --- | --- |
| `✅ 已有` | 当前实现已满足主要目标，并有代码或截图证据 |
| `◐ 部分` | 已有基础，但层级、内容、交互、响应式或质量不足 |
| `❌ 缺失` | 当前没有对应内容或能力 |
| `⏳ 待验证` | 代码可能存在，但尚未完成真实浏览器、设备或内容验收 |
| `— 不采用` | 经产品判断不适合 ScoreTransposer，明确记录原因后不实施 |

### 2.2 优先级定义

| 优先级 | 含义 |
| --- | --- |
| `P0` | 直接影响首屏理解、首次使用、核心转化或品牌方向，优先解决 |
| `P1` | 显著影响专业质感、内容证明、交互完整性或移动端体验 |
| `P2` | 增强信任、增长、内容运营和长期品牌能力 |
| `P3` | 实验性增强，必须在核心体验稳定后实施 |

### 2.3 每次改版的更新规则

每次前端任务完成后，至少更新：

- 对照条目状态。
- 实现文件与组件名。
- 桌面端和移动端截图位置。
- 真实内容或测试样本。
- 已知限制。
- 是否通过键盘、响应式、加载和视觉回归验证。

仅有代码提交、Figma 图或静态截图，不等于条目完成。涉及上传、模式切换、播放、案例筛选、FAQ、定价或移动导航的条目，必须有真实交互证据。

## 3. 观察范围与证据边界

### 3.1 本轮直接观察范围

- 观察日期：2026-08-18。
- 观察对象：三个网站无需登录即可访问的公开首页及其完整长页面。
- 主要视口：2560 × 1223 桌面端。
- ChatPPT 文档高度约 4,928px。
- BeatViz 文档高度约 34,403px。
- MiniMax H3 文档高度约 11,788px。
- 检查内容：页面结构、首屏、导航、排版、颜色、组件、按钮、案例、信任内容、转化路径、交互样式和响应式代码信号。

### 3.2 尚未直接验证的范围

- 三站登录后的完整工作区。
- 全部付费页、帮助页、博客文章和账户页面。
- 三站在 390px、768px、1024px 等视口下的逐页人工截图验收。
- 动画帧率、真实网络性能、无障碍审计和低端设备表现。

因此，本文对移动端和性能的部分判断属于“从公开 DOM、响应式类和页面结构得出的实施参考”，后续仍需专项验证。

## 4. ScoreTransposer 产品与设计护栏

参考站的优秀前端方法必须服从 ScoreTransposer 的产品模型：

- **视觉方向已经冻结为浅色网站。** 页面、导航、页脚、工作台外壳和章节背景均使用白色、浅灰或低饱和浅紫，不设置深色主题或整段深色内容区；真实产品截图中的历史深色界面只作为待更新的证据资产，不定义网站主题。
- PDF、图片、扫描件和音频是导入来源，不是可编辑真相源。
- MusicXML 是主要交换格式。
- 内部 Score JSON 是编辑、移调、播放、练习、版本与导出的应用真相源。
- OMR 输出首先是带置信度与诊断的候选修订，经过用户检查后才能提升为确认修订。
- 五线谱、简谱、移调、播放、导出和协作必须回到同一个乐谱工程。
- 不为模仿参考站而创建互不关联的一次性转换器。
- 不承诺所有扫描谱都能一键达到出版级质量。
- 不用漂亮动效掩盖识别不确定性、付费边界或尚未上线的功能。
- 中国市场的简谱必须是一等能力，包括调中心、级数、八度点、时值线、变音、歌词和往返预期。

## 5. 总体学习结论

三个网站功能不同，但共享同一个核心方法：

> 把产品体验直接做成营销页面本身，让用户在第一屏看到输入、处理方式和输出结果。

它们共同完成了以下转换：

| 传统工具官网 | 三个参考站的做法 |
| --- | --- |
| 先介绍公司与技术 | 先展示用户能得到的结果 |
| 只有“立即体验”按钮 | 首屏出现输入框、模式切换、生成器或真实工作台 |
| 用图标解释功能 | 用成品、模板、视频和真实案例证明功能 |
| 全页统一卡片 | 用全宽背景、媒体、卡片、深浅区块建立节奏 |
| 所有按钮权重接近 | 一个主 CTA，其他动作明显降级 |
| 功能堆叠 | 按用户工作流和决策过程组织页面 |
| 文案解释信任 | 真实输入输出、数据、案例和评价建立信任 |

对 ScoreTransposer 来说，目标不是再做一页“乐谱功能说明”，而是做成：

```text
上传一页真实乐谱
→ 看见识别候选和不确定位置
→ 切换五线谱、简谱、移调与播放结果
→ 理解如何继续校对和导出
```

### 5.1 三站快速对照

| 维度 | ChatPPT | BeatViz | MiniMax H3 | ScoreTransposer 应采用 |
| --- | --- | --- | --- | --- |
| 核心气质 | 清楚、专业、商业 SaaS | 沉浸、音乐、潮流、强品牌 | 电影结果与真实工具融合 | 专业可信为底，增加音乐品牌和真实工作台 |
| 首屏构图 | 左输入、右成品的双栏 | 中央巨型标题与媒体舞台 | 视频背景中央嵌入生成器 | 左上传、右乐谱结果，或中心上传器叠加真实结果 |
| 主色策略 | 白/浅灰 + 紫蓝 | 黑 + 荧光黄绿 | 白/浅灰 + 紫色，黄色促销 | 中性纸面 + 独立品牌色；绿色保留给确认状态 |
| 主要证明 | PPT 成品和模板库 | 视频、社区作品和评价 | 真实输入、参数、输出和案例来源 | 扫描、候选、确认、简谱、移调与播放同源案例 |
| 页面节奏 | 紧凑、明暗切换清楚 | 很长、媒体载体持续变化 | 中长页、宽窄区块和案例交替 | 控制长度，避免连续 Panel，设置一处沉浸高潮 |
| 转化方式 | 输入区 + 注册/生成 | 强主 CTA 多次重现 | 首屏可配置工具 + 页面末尾闭环 | “免费识别一页”贯穿首屏、案例后和页尾 |
| 最值得借鉴 | 低理解成本和案例画廊 | 品牌记忆和音乐情绪 | 营销页即工具、复杂参数分层 | 三者组合，不复制任一站的外观 |

## 6. ChatPPT 前端学习记录

### 6.1 设计定位

ChatPPT 是明亮、理性、专业的商业 SaaS 风格。它的核心优势不是视觉猎奇，而是极低的理解成本、稳定的信息层级和成熟的转化结构。

### 6.2 页面叙事顺序

```text
导航
→ 首屏生成器与 PPT 成品
→ 三步工作流
→ 模板案例库
→ 选择理由
→ 深色用户评价
→ 最终 CTA
→ 页脚
```

这一顺序覆盖了用户的完整决策过程：

1. 这是什么。
2. 我怎么开始。
3. 最终结果长什么样。
4. 操作是否复杂。
5. 能否满足我的场景。
6. 是否有人使用并认可。
7. 我现在该做什么。

### 6.3 导航

- 顶部导航高度约 65px。
- 白色背景，轻微底部分隔。
- 左侧品牌，中间主导航，右侧语言、登录和注册。
- 主导航数量克制：首页、模板库、价格。
- 登录为文字或弱按钮，注册为蓝色实心主按钮。
- 导航不会与首屏争夺注意力。

可迁移到 ScoreTransposer：

- 导航只保留扫描、转换、移调、编辑、定价等主要意图。
- “免费识别一页”是右侧唯一高权重动作。
- 登录、语言、升级保持次级。
- 不在导航放所有后台模块。

### 6.4 首屏结构

- 大面积浅色背景，带极淡的紫蓝环境光。
- 双栏结构：左侧价值主张与输入，右侧真实成品预览。
- 左侧标题先讲行为，再用紫蓝渐变强调最终结果。
- 标题约 60px、800 字重、紧字距、接近 1.0 的行高。
- 正文长度短，只解释输入主题后可得到专业 PPT。
- 输入区内部有 PPT 生成、PPT 优化、AI 原生 PPT 三个模式。
- 右侧不是装饰插画，而是完整 PPT 工作界面和生成结果。
- 首屏底部放置用户量、生成量、模板量等信任数据。

最重要的可复用关系：

```text
左侧“我要做什么” + 右侧“我会得到什么”
```

### 6.5 色彩

- 页面基础：白色、浅灰蓝、深蓝黑文字。
- 品牌与主要操作：紫色、蓝色。
- 环境装饰：极淡粉色、黄色、紫色光晕。
- 状态标签：绿色、红/橙等局部色。
- 深色仅用于用户评价等情绪切换区。
- 高饱和颜色不会在所有卡片重复出现。

### 6.6 排版

- H1 约 60px / 800 / 60px 行高。
- H2 约 36px / 700 / 40px 行高。
- H3 约 18px / 700 / 28px 行高。
- 正文约 16px / 24px 行高。
- 主要使用 Inter 一类现代无衬线字体。
- 标题、正文、辅助信息和标签的字号层级清晰。
- 重点标题通常控制在两行以内。

### 6.7 组件体系

- 公告/升级标签。
- 顶部导航。
- 模式分段控制器。
- 大型文本输入工作台。
- 产品结果预览。
- 数据信任条。
- 三步工作流卡。
- 模板分类筛选。
- 3 × 2 模板画廊。
- 优势卡片。
- 深色用户评价卡。
- 最终注册 CTA。

### 6.8 模板案例区

- 案例首先展示完整成品，不首先展示文字。
- 使用统一宽高比、统一卡片结构和不同内容风格。
- 分类筛选位于画廊上方。
- 卡片底部只保留名称、比例、类型和状态标签。
- 热门、新品、教育等标签负责快速扫描。
- 鼠标经过后有进入详情的视觉暗示。

ScoreTransposer 对应做法：

- 建立真实乐谱案例库，而不是抽象功能卡片库。
- 分类可以是独奏、钢琴、合唱、歌词、简谱、移调、低清扫描、多页 PDF。
- 卡片显示输入类型、页数、声部、识别状态和是否人工确认。

### 6.9 页面节奏

- 首屏浅色、工作流白色、模板浅灰、优势白色、评价深色、CTA 浅色。
- 不同背景承担章节分隔，不依赖每一块都有外边框。
- 深色评价区形成视觉换气和信任高潮。
- 页面总长度适中，内容没有无限扩张。

### 6.10 交互与动效

- 导航和按钮有统一颜色过渡。
- 模式切换有明确激活态。
- 模板分类为可点击筛选。
- 按钮、卡片和箭头提供轻微反馈。
- 动效服务于状态识别，不喧宾夺主。

### 6.11 最值得借鉴

1. 低理解成本的首屏。
2. 输入与结果的并列关系。
3. 用成品库代替功能图标堆叠。
4. 清楚的主次 CTA。
5. 明暗区块建立页面节奏。
6. 统一且克制的商业设计系统。
7. 适合专业工具的可信感。

### 6.12 不应直接复制

- 通用白底紫蓝 AI SaaS 外观容易失去音乐品牌个性。
- PPT 的 16:10 横向模板比例不适合所有乐谱案例。
- 大量模板图若没有真实业务数据，会成为纯装饰。
- 用户量等数字必须真实可验证，不能为了版式仿造。

## 7. BeatViz 前端学习记录

### 7.1 设计定位

BeatViz 是高对比、沉浸、娱乐和音乐文化导向的品牌站。它的核心优势是强记忆点、强情绪和媒体内容编排。

### 7.2 页面叙事顺序

```text
荧光公告栏
→ 沉浸式首屏
→ AI 导演介绍
→ 巨型视觉宣言
→ 三工具工作流
→ 创作者评价
→ 核心价值与功能
→ 音乐生成场景
→ 社区作品
→ 强功能长区
→ 为什么选择
→ 适用人群
→ 社区信任
→ 定价
→ 最终 CTA
→ 博客
→ FAQ
```

页面非常长，但不断更换内容载体，因此不会完全变成长文档。

### 7.3 导航与公告

- 顶部约 52px 荧光黄绿色公告栏。
- 公告栏包含 NEW、版本说明和 Try Chat 2.0 CTA。
- 黑色导航与首屏融为一体。
- 左侧品牌，右侧 Help、Explore、Tools、Pricing、Discord、语言和 Start for Free。
- Discord 使用平台品牌色，Start for Free 使用白底黑字，主次清楚。

可迁移原则：

- 只有真实活动、新功能或限时信息才显示公告栏。
- 公告栏必须有关闭能力并记住状态。
- 导航 CTA 必须在复杂背景上保持可读。

### 7.4 首屏结构

- 黑色背景与透视网格形成舞台和未来空间。
- 主标题居中，约 96px、900 字重、120px 行高。
- 第一行使用绿色轮廓字，第二行白色实心字。
- 简短副标题解释音乐到视频的价值。
- 主 CTA 使用荧光绿色与发光阴影。
- 次 CTA 使用透明/深色背景和弱边框。
- 首屏底部直接露出下一段大型媒体内容，提示继续滚动。

### 7.5 品牌与颜色

- 基础色：纯黑或接近纯黑。
- 主要强调：荧光黄绿。
- 内容：白色及不同透明度白色。
- 社区或平台动作：Discord 蓝紫。
- 品牌标识和部分按钮使用粉紫渐变。
- 高饱和色集中在 CTA、公告和状态，不平均分配。

### 7.6 排版

- 首屏 H1 约 96px / 900。
- 大章节标题常见 48～72px / 700～900。
- 卡片标题 18～24px / 600～700。
- 正文 16px / 24px。
- Geist、Satoshi 一类现代无衬线字体。
- 巨型标题与小型标签形成极端尺度对比。
- 文字本身成为视觉图形，而不是只承担阅读。

### 7.7 媒体与内容编排

- 全宽视频和大图片承担核心叙事。
- 三工具区不是三张普通功能卡，而是完整工作流展示。
- 社区作品和用户评价大面积出现。
- “有音乐”和“没有音乐”分别成为完整场景。
- 功能 Bento 区混合不同卡片尺寸和媒体比例。
- 定价、博客和 FAQ 仍延续品牌视觉，不像外接模板。

### 7.8 微交互

- 主按钮悬停放大约 1.02～1.05。
- 按下缩小约 0.98。
- 卡片悬停后标题变为荧光绿色。
- 导航和语言按钮有透明度、背景和边框变化。
- 圆形关闭按钮提供旋转或颜色反馈。
- 动效持续时间主要在 200～300ms。
- 动效语言与音乐节奏和舞台感一致。

### 7.9 页面节奏

- 通过大标题、全屏媒体、工具说明、社区作品、定价和 FAQ 不断切换节奏。
- 黑色底色不变，但利用媒体亮度、卡片密度和荧光色重建章节差异。
- 每隔若干屏出现新的视觉高潮。
- CTA 在长页面中多次重现。

### 7.10 最值得借鉴

1. 强烈且一致的音乐品牌个性。
2. 背景本身表达产品类别。
3. 把文字排版做成品牌图形。
4. 用媒体、作品和社区构建信任。
5. 微交互统一且有节奏。
6. 页面内容载体不断变化。
7. 即使功能复杂，主 CTA 仍然明确。

### 7.11 ScoreTransposer 可迁移方式

- 用五线谱线、播放光标、小节线和扫描噪点建立音乐视觉母题。
- 增加一个浅色沉浸演示舞台，用媒体尺寸、谱线、播放光标和空间层次制造高潮，不依赖深色背景。
- 演示“扫描图 → 候选谱 → 确认谱 → 播放”的动态过程。
- 卡片悬停时高亮真实小节或播放局部音符。
- 让首页形成至少一次明显的情绪高潮。
- 用真实教师、编曲者、学生和合唱团队工作流替代抽象行业卡。

### 7.12 不应直接复制

- 不采用全站纯黑和荧光色作为长时间制谱工作区。
- 不采用 34,000px 级页面长度作为目标。
- 不在没有内容资产和性能预算时大量使用自动播放视频。
- 不让娱乐化品牌语言削弱乐谱校对的专业与可信度。
- 不使用高强度发光效果标记普通按钮和表单。

## 8. MiniMax H3 前端学习记录

### 8.1 设计定位

MiniMax H3 把电影感结果展示、明亮商业界面和真实生成器组合在同一首屏。它是三个参考站中“营销页即工具”完成度最高的案例。

### 8.2 页面叙事顺序

```text
优惠公告
→ 白色导航
→ 全屏视频背景与真实生成器
→ 创作者案例轮播
→ 多模态输入输出案例
→ 产品创作台叙事
→ 产品定义
→ 选择理由
→ 适用人群
→ 核心能力
→ 三步流程
→ 社交评价
→ FAQ
→ 最终 CTA
```

### 8.3 导航与促销

- 顶部黄色活动栏高度约 40px。
- 活动栏包含倒计时、折扣说明、年付入口和关闭按钮。
- 下方白色导航约 54px。
- 左侧品牌，中间产品、功能、案例、定价，右侧语言和免费开始。
- 导航标签约 13px、600 字重，带轻微字距。
- 定价旁直接显示折扣标签。

### 8.4 首屏结构

- 全屏黑白电影视频承担结果氛围。
- 中央标题使用紫色/紫色渐变突出品牌。
- 副标题直接说明文字或图片生成 2K 含音频视频。
- 三个能力标签快速解释产品边界。
- 中央嵌入白色大型生成器卡片。
- 生成器不是示意图，而是可理解的真实产品结构。
- 页面右下提供声音控制和安装入口等悬浮动作。

### 8.5 生成器分层

生成器内部把复杂选项拆为五层：

1. 产品层：AI 视频 / AI 图片。
2. 模式层：文生视频 / 图生视频 / 全能参考。
3. 输入层：提示词与参考内容。
4. 参数层：模型、时长、清晰度、画幅。
5. 动作层：示例、签到、免费开始。

不同层级通过尺寸、背景、胶囊控件和位置区分，不把所有设置平铺成同等权重的表单。

ScoreTransposer 对应分层：

1. 产品层：扫描识谱 / 简谱转换 / 移调。
2. 输入层：PDF / 图片 / MusicXML / MIDI。
3. 任务层：识别页码、声部、歌词和识别方式。
4. 输出层：候选五线谱 / 简谱 / MusicXML / MIDI / PDF。
5. 动作层：试用示例 / 免费识别一页。

### 8.6 色彩

- 页面基础：`#F7F8FA` 一类浅灰和白色。
- 文字：深黑和不同层次的中灰。
- 品牌与主 CTA：紫色/紫粉渐变。
- 促销：黄色。
- 状态和次级动作使用低饱和色。
- 每种高饱和颜色承担单一职责。

### 8.7 排版与宽度

- 重点章节 H2 常见 36～48px、700 字重、负字距。
- 正文常见 16px / 24px。
- 使用 Outfit 一类圆润现代无衬线字体。
- 重点正文采用约 768px 宽度。
- 桌面章节背景铺满视口，但内容不能只使用一个宽度：沉浸演示层用 16～32px 安全边距接近全屏，核心功能层居中并限制在约 1320px，核心文字再收窄到约 760～900px。
- 正文通过自身阅读宽度保持可读性；大乐谱、案例画廊和工作台预览可以接近全屏，多列业务卡片则使用居中的核心功能宽度。
- 章节上下留白常见 80～96px。
- 宽窄内容区交替，避免所有内容落在同一网格宽度。

### 8.8 案例与证明

- 创作者案例使用横向轮播和视频预览。
- 多模态案例解释真实输入文件和输出结果。
- 显示任务类型、时长、画质、参考内容和工作流。
- 标明案例来源、作者和原帖入口。
- 产品介绍不是只写能力，而是结合完整成片和创作步骤。
- 社交评价使用真实公开内容格式。

### 8.9 长页内容组织

- 大量 SEO 文案被拆入案例、优势、场景、流程和 FAQ。
- 章节首先给短标题与一句话，再展示媒体或卡片。
- 复杂说明通过标签、步骤、参数和对比降低阅读压力。
- FAQ 使用折叠模式，不默认展开全部答案。
- 页面末尾回到与首屏一致的主要动作。

### 8.10 最值得借鉴

1. 首屏嵌入真实生成器。
2. 电影结果与白色工具面板形成前后景关系。
3. 复杂参数分层，而不是平铺表单。
4. 真实输入输出案例和来源说明。
5. 大量内容仍保持清楚的视觉层级。
6. 宽窄容器和章节留白建立节奏。
7. 首屏与页面末尾形成转化闭环。

### 8.11 不应直接复制

- 不使用与乐谱无关的电影视频作为视觉主体。
- 不让活动倒计时长期常驻或制造虚假稀缺。
- 不在首页暴露过多仅供高级用户理解的识别参数。
- 不把未上线功能伪装成可点击模式。

## 9. 三站共同的前端设计基准

### 9.1 信息架构

一个成熟工具首页应回答：

1. 这是什么。
2. 能给我什么结果。
3. 我怎样开始。
4. 结果是否真实可信。
5. 需要多少步骤。
6. 是否适合我的场景。
7. 免费与付费边界是什么。
8. 现在下一步做什么。

推荐叙事顺序：

```text
导航
→ 结果型首屏与真实入口
→ 可核实事实
→ 真实案例
→ 输入输出对比
→ 工作流
→ 完整工具链
→ 使用场景
→ 社会证明
→ 定价
→ FAQ
→ 最终 CTA
→ 页脚
```

### 9.2 首屏

- 首屏必须同时出现价值主张、主要操作和真实结果。
- 用户在一屏内理解输入、处理和输出。
- 主要标题控制在两到三行。
- 正文控制为一段，不在首屏解释全部技术边界。
- 主 CTA 只有一个。
- 次 CTA 最多一个。
- 登录、注册和升级不与首次试用争夺注意力。
- 桌面端优先双栏或中心工具布局。
- 移动端首屏必须仍能看到真实结果预览，而不是把结果完全折叠。

### 9.3 内容证明

- 成品优先于功能图标。
- 真实输入优先于抽象插图。
- 案例要显示任务类型、输入、输出和限制。
- 数据必须可核实。
- 用户评价必须真实且获得适当授权。
- 未获得真实用户评价前，宁可使用验证样本和操作证据。

### 9.4 视觉层级

- 中性基础色 + 一个主强调色 + 一个受控的活动/状态色。
- 高饱和颜色只用于 CTA、品牌重点和重要状态。
- 不用边框包围所有章节。
- 通过背景、留白、媒体和尺寸建立章节层级。
- 同一视口的容器嵌套边界不超过两层。
- 大标题、正文、辅助信息和标签形成稳定比例。

### 9.5 组件

- 导航、按钮、标签、模式切换、案例卡、流程、FAQ 和 CTA 有明确专用组件。
- 不用一个通用 Panel 承担所有视觉角色。
- 可交互卡片与纯展示卡片的样式不同。
- 激活、悬停、按下、禁用、加载和错误状态完整。
- 表单复杂度通过分层和渐进披露管理。

### 9.6 动效

- 动效解释状态、关系和结果，不作为无意义装饰。
- 悬停反馈主要为颜色、1～2px 位移或 1.01～1.03 缩放。
- 按下可使用约 0.98 缩放。
- 普通状态过渡控制在约 180～300ms。
- 长动画提供暂停或静态替代。
- 支持 `prefers-reduced-motion`。

### 9.7 转化

- CTA 文案描述动作与结果，不使用含糊的“了解更多”。
- 主 CTA 在首屏、案例/工作流后和页面末尾重复。
- 免费边界紧邻首次操作说明。
- 付费入口不抢占首次价值验证。
- 定价说明结果、配额和限制，而不是只显示价格。

### 9.8 响应式

- 导航在移动端使用明确菜单，不依赖隐藏滚动条的横向导航作为唯一方案。
- 首屏标题、上传、CTA 和结果预览在 390px 内完整可理解。
- 所有主要操作目标不小于 44px。
- 乐谱、表格和编辑器有明确的缩放或横向浏览策略。
- 模式切换和筛选控件允许换行或水平滚动，并有可发现性。
- 不因为移动端压缩而隐藏关键结果或信任信息。

### 9.9 无障碍与性能

- 保持可见键盘焦点。
- 模式切换、标签和 FAQ 使用正确语义与状态。
- 视频默认静音，提供暂停和字幕/文字替代。
- 颜色不是状态的唯一表达。
- 乐谱诊断同时提供符号、文字和位置说明。
- 首屏媒体有固定尺寸，避免布局跳动。
- 首屏只加载必要媒体，长页视频和案例延迟加载。
- 为真实谱面缩略图提供适合展示尺寸的衍生图，不直接加载原始大文件。

### 10.3 当前设计体系冲突

项目目前同时存在两套方向：

1. 早期 “The Sonic Manuscript” 深色、玻璃、渐变、无边框设计规范。
2. 当前 `sonata.css` 后部覆盖的浅色、绿色、实线边框、商业工具主题。

具体冲突包括：

- 早期规范禁止使用 1px 实线边框；当前主题大量使用 1px 边框。
- 早期规范要求暗色层级与玻璃效果；当前主题关闭玻璃和环境背景。
- 早期规范使用大圆角和渐变；当前主题把圆角统一收窄到 6～8px 并移除阴影。
- `sonata.css` 同一选择器存在多轮后置覆盖。
- 移动端首屏预览先被压缩到 84px，随后又通过第二个同断点规则恢复完整高度。
- 导航在 1500px 就换为两行并使用横向滚动，容易在普通笔记本上显得拥挤。

在任何大规模视觉改版前，应先确定唯一设计方向，并把令牌和组件状态整理为单一来源。

### 10.4 当前首页主要问题

- 公开首页首屏在桌面端仍是单列结构。
- 静态产品截图位于文案之后，输入与结果关系较弱。
- 首屏没有真实上传器或可理解的任务配置。
- 首屏最多出现开始、注册、购买三个动作，主次不够集中。
- 大量章节连续使用 Panel、sunken Panel、feature-grid 和 access-grid。
- 视觉内容少，文字与边框容器多。
- 案例区缺少真实输入输出画廊。
- 使用场景主要是文字卡。
- FAQ 默认全部展开为卡片。
- SEO、隐私和条款内容占用较多首页长度。
- 没有独立的浅色沉浸式产品演示高潮。
- 没有真实用户评价或等价的可信案例证据区。
- 页面末尾缺少与首屏一致的强转化闭环。

## 14. 已冻结的视觉方向

视觉方向已经确定为浅色网站，并已完成首轮代码与实机验证。后续迭代必须保持以下约束：

### 14.1 气质组合

- 使用 ChatPPT 的清楚与可信。
- 使用 MiniMax H3 的工具嵌入和输入分层。
- 使用 BeatViz 的音乐品牌个性与一处沉浸式高潮。
- 所有页面外壳和章节保持浅色；沉浸感由谱线、空间、媒体和动效建立，不使用整段深色背景。
- 不采用全站霓虹或全站玻璃。
- 不回到普通后台式绿白表格站。

### 14.2 色彩职责

- 基础背景：冷白、纸白、轻灰。
- 主要文字：深墨色，而非纯黑。
- 品牌主色：从紫蓝、钴蓝或其他与确认绿色区分的色相中选定一种。
- 成功/确认：绿色。
- 待检查/低置信度：琥珀色。
- 错误：红色。
- 信息与播放：可使用蓝青色，但必须与品牌色协调。
- 活动色只在真实活动中出现。

### 14.3 排版建议起点

- H1：桌面 56～72px；移动 36～42px；行高 1.04～1.10。
- H2：桌面 40～48px；移动 30～36px。
- H3：20～24px。
- 正文：17～20px；行高 1.55～1.7。
- 辅助文字：13～15px。
- 标签：11～13px，但不得影响可读性。
- 标题可使用更有编辑感的字体，功能 UI 使用高可读无衬线字体。
- 中英文、数字、音乐符号和简谱记号必须一起测试。

### 14.4 空间与形状建议起点

- 页面骨架采用三级宽度，不允许用一个通用容器控制所有内容：章节背景铺满视口；演示层用 `clamp(16px, 2vw, 32px)` 安全边距；核心功能层居中并以约 1320px 为桌面上限。
- 正文阅读宽度约 680～800px，标题与核心说明约 760～900px；大媒体、案例网格和工作台预览才使用接近完整的可用宽度。
- 章节上下留白：80～112px。
- 重大媒体章节：112～144px。
- 卡片间距：20～28px。
- 大工作台圆角：18～24px。
- 普通卡片圆角：14～18px。
- 控件圆角：10～14px。
- 标签使用胶囊形，但普通按钮不必全部胶囊化。
- 一般章节不使用外层大卡片。

## 27. 改版记录：2026-08-19 / 演示近全屏、核心内容居中

本节根据 BeatViz 首屏截图的再次核对修订第 26 节。第 26 节记录了从“过窄”向“更宽”调整的历史过程；此后的页面新增与验收以本节的三级宽度规范为准。

### 27.1 从对标界面确认的规则

- “铺满屏幕”指的是背景和演示舞台，不代表标题、说明、按钮和核心功能都贴近屏幕两侧。
- 视觉演示承担沉浸感，可以接近视口全宽；核心文字承担理解和转化，应保持稳定中心轴和较短阅读行长。
- 核心功能卡可以叠放在大演示画面上，但卡片本身仍要居中且明显窄于演示画面，由此形成“文字 → 操作 → 结果”的纵向焦点。
- 英文 H1 优先保证桌面一行居中；通过适度减小字号、扩大标题自己的最大宽度实现，不通过把所有业务内容一起拉满实现。
- 首页不再讨论“是否全宽”这一二选一问题，而是明确区分背景层、演示层、核心层和阅读层。

### 27.2 本站三级宽度令牌

| 层级 | 主要内容 | 当前规则 | 视觉目的 |
| --- | --- | --- | --- |
| 背景层 | 章节底色、分隔与氛围 | `width: 100%` | 让页面形成连续、完整的桌面画布 |
| 演示层 | Hero 乐谱预览、真实案例、过程舞台、播放舞台、场景画廊 | `calc(100% - 2 × clamp(16px, 2vw, 32px))` | 接近全屏，突出产品结果与真实画面 |
| 核心功能层 | 上传卡、能力矩阵、证明和功能详情内容 | 居中，最大约 `1320px` | 保持信息组织稳定，不随超宽屏无限拉长 |
| 核心文字层 | H2、说明、转化文案 | 居中，约 `760～900px` | 控制阅读行长和视觉焦点 |

### 27.3 Hero 的具体处理

- Hero 标题、说明、主次按钮和免费规则围绕同一条中心轴排列。
- 英文 H1 使用较克制的 `clamp(2.35rem, 3.1vw, 3.75rem)`，桌面标题容器可以更宽，但文字始终居中。
- 上传卡最大约 `920px`，居中悬浮在近全屏乐谱演示之前；它是核心操作，不跟随演示图铺满。
- 乐谱预览使用演示层宽度和更大的桌面高度，成为首屏的主要产品证明；移动端恢复普通文档流，避免悬浮卡遮挡内容。
- Hero 下方的章节标题从左右分栏改为居中单列，正文最大约 `760px`，解决视觉重心过散的问题。

### 27.4 浏览器测量基线

## 28. 改版记录：2026-08-19 / 乐谱限宽、单一浅色产品与英文两行规范

本节进一步明确第 27 节中的“演示层”并不是所有媒体都必须近全屏。视频、场景画廊可以用沉浸式宽度；需要辨认五线、音符和编辑关系的乐谱工作区必须优先保证比例与可读性。

### 28.1 乐谱演示宽度例外

- 首页首屏的乐谱结果预览改用与核心内容一致的居中宽度，最大 `1320px`；章节背景仍然铺满视口。
- 乐谱不再跟随超宽屏无限横向伸展，避免五线距离、留白和音符尺度被视觉上“拉散”。
- 上传入口、乐谱结果和下一个核心标题保持同一中心轴，形成稳定的“操作 → 结果 → 下一步”阅读路径。
- 视频或连续案例画廊仍可使用近全屏舞台；谱面、表单和核心功能文字使用居中内容层。媒体宽度由内容性质决定，不再执行一刀切的全宽规则。

### 28.2 单一浅色产品主题

- 官网与产品工作台只保留一套浅色主题，不提供与当前品牌无关的深色产品示例。
- All examples、Recognition、Conversion、Transform、Editing、Practice、Export 中的图片全部重新从真实运行产品截取，不通过后期反色或伪造界面生成。
- 实际产品页的旧深色卡片、局部面板、输入框、选择框和只读字段统一为白色或浅灰底；状态继续由文字、图标、描边和辅助色共同表达。
- 截图证据保留真实 Score JSON、MusicXML、简谱、播放、移调、编辑、教学和计费流程，浅色化不能把真实功能替换成装饰性样机。

### 28.3 英文标题的桌面规则

- 核心章节英文标题在桌面目标为 `1～2` 行，优先删减重复修饰词，再适度降低字号和放宽标题容器。
- 使用 `text-wrap: balance` 平衡两行长度；不在介词、冠词或固定短语内部人为插入换行。
- 标题默认最大宽度提升到约 `960px`，分栏/长句标题可到 `1100px`；桌面字号上限收敛为约 `3.15rem`。
- 移动端允许自然增加行数，但必须保持语义短语完整、无逐词堆叠和横向溢出。

### 28.4 本轮证据更新

### 28.5 核心操作与真实证据不得互相遮挡
