## 1. 产品结论

ScoreTransposer 已拥有可销售的乐谱处理底座，但正式站还没有完整成交路径。商业化 MVP 不继续扩张教学、协作或实验性 AI 功能，而是把现有能力收敛为一条可理解、可体验、可购买、可交付的主链路：

> 注册 → 免费处理一页 PDF/图片 → 查看 OMR 五线谱候选预览 → 付款开通 → 校对、简谱转换、移调、播放与完整导出。

## 2. 核心用户与需求

### 2.1 首要用户

- 持有清晰五线谱 PDF/图片、需要转换成简谱的音乐教师和学习者。
- 需要快速移调、试听或导出 MusicXML/MIDI/PDF 的编曲和排练用户。
- 通过 Google 搜索具体工具词进入网站、此前不了解品牌的新用户。

### 2.2 用户必须得到的结果

- 上传后明确看到任务是否排队、处理中、完成或失败。
- OMR 输出必须被标识为“候选稿”，并能看到五线谱预览和诊断，不承诺一键出版级准确。
- 付款成功后自动获得权益，不需要人工兑换激活码。
- 完整导出、第二次识谱和多页识谱必须经过付费权益检查。

## 3. 商业化 MVP 范围

### 3.1 免费层

- 必须注册登录。
- 每个账户终身 1 次 OMR 预览。
- 输入为 1 页 PDF，或 1 张 PNG/JPG/WEBP/TIFF 图片。
- 可以查看识别任务状态、候选五线谱预览和基础诊断。
- 不允许下载 MusicXML、MIDI、PDF、PNG/SVG、简谱文本、Score JSON 或音频文件。
- 不允许第二次 OMR、批量处理、多页处理、音频转谱或教学协作。

### 3.2 付费层

- 多次和多页 PDF/图片 OMR。
- MusicXML、MIDI、Score JSON、简谱文本导入。
- OMR 候选确认与结构化校对。
- 五线谱/简谱转换、移调、播放练习。
- MusicXML、MIDI、PDF、PNG/SVG、简谱、WAV/MP3 等完整导出。
- 保存工程和版本历史。

### 3.3 暂不作为首发卖点

- 音频转谱：保持 Preview/实验功能。
- 教学、课堂、LTI、实时协作、学校席位：代码保留，不进入首购主路径。
- MuseScore 级自由排版和全功能制谱：不在 MVP 承诺中。
- 自助退款：第一阶段由收款平台后台执行，网站通过 Webhook 同步账单和权益状态。

## 4. 核心流程

### 4.1 搜索到体验

1. 用户从 Google 进入单一意图页面。
2. 点击“免费转换一页”。
3. 注册或登录。
4. 自动进入乐谱工程库的 OMR 上传区。
5. 上传一页 PDF 或一张图片。
6. 查看排队、处理进度、候选五线谱预览与限制提示。
7. 点击升级，进入正式支付。

### 4.2 付款到权益

1. 已注册用户选择个人订阅。
2. API 创建带幂等键的 Paddle Transaction 和本地订单。
3. Paddle Checkout 完成付款并发送签名 Webhook。
4. 系统写入订单/订阅账本并自动激活当前账户。
5. 成功页轮询订单状态，确认后进入乐谱工程库。
6. 用户可继续处理多页文件、校对并完整导出。

### 4.3 退款

1. 运营人员在 Paddle 后台执行全额或部分退款。
2. Webhook 同步退款金额和账单状态。
3. 全额退款按既定订阅策略取消或停止权益；部分退款只更新账单。
4. 用户在账单页看到退款状态。

## 5. 功能需求

### P0：成交阻断

- FR-001：注册成功后直接进入免费 OMR 上传区，而不是被权益墙重定向。
- FR-002：未付费账户只能创建 1 个 `omr_import` 任务。
- FR-003：免费 PDF 输入必须在任务创建前验证为最多 1 页；单张图片视为 1 页。
- FR-004：免费用户可以读取自己的工程、任务状态和 MusicXML 候选预览。
- FR-005：所有导出和结构化修改继续要求有效付费权益。
- FR-006：免费额度用尽后显示明确升级入口，不显示通用 403。
- FR-007：正式支付关闭时不得创建测试订单或跳转到 staging。
- FR-008：正式支付开放前必须完成一次真实付款、一次自动开通和一次退款同步验收。

### P1：首发产品一致性

- FR-101：首页、功能页、注册页和工作区统一表述 PDF 与图片支持范围。
- FR-102：音频转谱和教学能力不得占据主 CTA。
- FR-103：OMR 完成后必须显示候选稿、置信度/诊断和人工检查提示。
- FR-104：支付、上传、识别和导出失败必须提供可行动的用户提示。

### P1：SEO 与测量

- FR-111：完成 Google Search Console 域名验证并提交 sitemap。
- FR-112：`/pdf-score-scanner` 在生产能力开放后进入 sitemap。
- FR-113：记录功能页访问、注册成功、首次 OMR 创建、付款成功四个漏斗事件。
- FR-114：每个 SEO 页面只覆盖一个主要搜索意图并链接到同一免费体验路径。

## 6. 非功能要求

- 免费额度在 API 强制执行，不能只依赖按钮禁用。
- 所有输出必须由 Score JSON/MusicXML 派生；PDF/图片不得成为编辑真相源。
- 支付创建必须幂等；Webhook 必须验签并可安全重复投递。
- 用户只能读取自己的试用工程和文件。
- OMR 失败不得消耗第二次隐藏额度；当前定义为“任务成功创建即使用一次”，失败可由客服人工补偿，后续根据真实订单量再增加自动补偿。

## 7. 阶段计划

### 阶段一：成交闭环

- 交付免费单页 OMR 预览权限和 UI。
- 注册后直接进入免费体验。
- 保持导出付费墙。
- 保留 Stripe 适配器，以 Paddle 作为当前最小可售链路；商户和 Live 凭据就绪前继续关闭生产付款。
- 完成真实付款、Webhook 开通、账单与退款验收后再打开生产付款开关。

验收标准：新用户无需人工介入即可注册、创建一次免费任务并看到候选预览；免费用户无法导出或创建第二个 OMR 任务；付费用户可正常继续完整流程。

### 阶段二：产品入口与交付一致性

- 统一官网、注册页、导航和工作区主按钮。
- 清理 PDF-only 旧口径。
- 隐藏非 MVP 主功能，完善 OMR 诊断和升级提示。

### 阶段三：SEO 获客闭环

- Search Console、sitemap、核心 OMR 页面和漏斗分析上线。
- 用真实展示量、点击、注册和付款数据优化页面，不批量制造低质量内容。

代码验收状态：已完成。生产验收状态：Search Console、sitemap、GA4 和两个生产前端均已上线；等待 Google 在 24 小时内生成完整事件列表，并根据首批真实访问建立漏斗基线。

### 阶段四：首批订单后优化

- 根据失败样本改进输入引导和识谱提示。
- 根据真实用量调整套餐、任务数和存储配额。
- 根据真实购买信号再决定启用 Stripe、学校版、协作和自助退款优先级。

## 8. 阶段一外部依赖

- 已审核可收款的 Paddle Live 账户；Stripe Live 账户不再阻塞当前阶段。
- Paddle Live API Key、Webhook Secret、Client-side Token、个人套餐 Price ID 和已批准的默认支付链接。
- 一笔真实测试付款及随后退款的授权。
- 生产环境变更窗口；只有上述验收通过后才设置后端 `PAYMENT_PROVIDERS=paddle`、前端 `NEXT_PUBLIC_PAYMENT_PROVIDERS=paddle` 和 `NEXT_PUBLIC_CHECKOUT_AVAILABLE=true`。

## 9. 成功指标

- 注册成功率。
- 注册后首次 OMR 创建率。
- OMR 完成并看到预览的比例。
- 免费预览到 Checkout 的点击率。
- Checkout 到付款成功率。
- 付款后首次完整导出成功率。

阶段三事件口径：`seo_landing_view`、`sign_up`、`free_omr_created`、`free_omr_preview_viewed`、`upgrade_click`、`begin_checkout`、`purchase`。事件禁止携带邮箱、文件名和乐谱内容，付款权益仍只由验签 Webhook 决定。

零流量阶段不设置虚假的绝对增长目标；先确保每个事件可测、每条链路可完成，再根据首批 20–50 个有效访问建立基线。
