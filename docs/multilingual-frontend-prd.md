# ScoreTransposer 九语言前端国际化改造 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档状态 | Draft v1.0，作为后续分阶段开发与验收基线 |
| 产品 | ScoreTransposer 官网与产品工作台 |
| 改造类型 | 前端国际化、响应式适配、本地化产品截图、多语言 SEO |
| 目标环境 | 每阶段先部署 staging，全部验收后再决定 production |
| 不包含语言 | 阿拉伯语及其他 RTL 语言 |
| 最后更新 | 2026-08-19 |

## 2. 背景与问题

ScoreTransposer 当前支持英语和简体中文，但实现仍以“英文 / 简体中文”二选一为主：

- `SUPPORTED_LOCALES` 当前只有 `en` 与 `zh-CN`。
- 官网约有 25 个文件、65 处 `zh-CN` 语言判断。
- 产品工作台约有 62 个文件、336 处 `zh-CN` 语言判断。
- 首页和功能页使用 10 张真实产品截图；截图内文字已固化在 PNG 中，不会跟随网页语言切换。
- 产品前端的 API 包装目前主要消费 `{ error: string }`；本项目明确允许后台与接口英文错误继续原样展示。

继续在现有条件判断中增加语言会迅速失去可维护性。本项目必须先建立统一国际化架构，再逐批迁移页面和素材。

## 3. 产品目标

### 3.1 支持语言

| 语言 | Locale | 用户显示名 |
| --- | --- | --- |
| 英语 | `en` | English |
| 简体中文 | `zh-CN` | 简体中文 |
| 繁体中文 | `zh-TW` | 繁體中文 |
| 日语 | `ja` | 日本語 |
| 韩语 | `ko` | 한국어 |
| 法语 | `fr` | Français |
| 西班牙语 | `es` | Español |
| 德语 | `de` | Deutsch |
| 俄语 | `ru` | Русский |

### 3.2 用户结果

1. 用户能够从官网和产品端选择上述任一语言。
2. 语言选择在刷新、页面跳转和官网到产品端跳转后保持一致。
3. 首页、功能介绍页和对应产品截图使用同一种语言。
4. 用户可用当前语言完成上传、识别、校正、简谱、移调、播放和导出主流程。
5. 翻译不会改变 Score JSON、MusicXML、文件、任务、支付或权限的业务含义。
6. 所有语言在主要桌面与移动断点下都保持可读、无重叠、无横向溢出。

### 3.3 成功指标

- 九种语言的关键路径词典完整率为 100%。
- staging 上九种语言关键路径无阻塞性英文残留；标准技术名词除外。
- 390、768、1280、1920、2560px 均无横向溢出。
- 官网核心桌面标题目标为 1～2 行，不出现逐词堆叠。
- 当前语言与首页产品截图语言匹配率为 100%。
- 切换语言不会修改乐谱工程数据、当前版本、任务状态或账户权限。
- 首页单语言资源继续满足既有 JavaScript、CSS 和图片预算。

## 4. 项目范围

### 4.1 本期包含

- `apps/www` 官网全局导航、页脚、首页、功能页及公共用户页面。
- `apps/app` 普通用户可见产品工作台。
- 语言配置、词典、格式化方法和缺失翻译检测。
- 官网多语言 URL、metadata、`hreflang`、canonical 与 sitemap。
- 语言选择器、Cookie 持久化及官网/产品端同步。
- 日语、韩语、繁体中文、俄语等字体与排版回退。
- 德语、法语、西班牙语、俄语长文案响应式适配。
- 10 张产品证据图的九语言映射与自动截图流程。
- 前端自有表单提示、空状态、成功状态和辅助功能文本的本地化；后台与接口错误保持英文。
- 多语言自动测试、浏览器断点测试和 staging 分阶段验收。

### 4.2 本期不包含

- 阿拉伯语及 RTL 布局。
- OMR、Audiveris、Score JSON、MusicXML、简谱算法或转调算法修改。
- 数据库表结构和乐谱数据迁移。
- 任务队列、文件存储、导出 worker 和音频生成逻辑修改。
- Stripe、Paddle、Webhook、订阅和权限计算逻辑修改。
- 自动翻译用户上传的文件名、歌词、标题、评论或自定义内容。
- 本期强制翻译管理员后台；管理员后台可暂时保持英文。
- 本地化邮件、短信、客服人工回复和第三方支付平台页面；如需支持，应另立需求。

## 5. 前端与后台边界

### 5.1 明确不动的后台能力

| 后台领域 | 本项目处理方式 |
| --- | --- |
| OMR 与 Audiveris | 不改识别流程、结果或诊断数据 |
| Score JSON / MusicXML | 不改模型、序列化、版本或文件内容 |
| 简谱与移调 | 不改算法、调号、拍号、音高和时值逻辑 |
| 播放与导出 | 不改 Tone.js 事件、MIDI、PDF、WAV、MP3 等生成逻辑 |
| 数据库 | 不新增语言相关业务表，不迁移现有工程数据 |
| 任务队列 | 不改任务类型、状态机和 worker |
| 登录与权限 | 不改身份验证、授权和试用规则 |
| 支付 | 不改价格、订单、Webhook、退款和权益账本 |

### 5.2 接口错误保持英文

本项目不为了国际化修改任何后台错误、接口错误或接口契约：

- 后台返回的英文 `error` 原样展示。
- API 请求失败、上传失败、下载失败和网络失败等接口错误保持英文。
- 不新增 `errorCode`，不建立后台错误的九语言映射。
- 不改 HTTP 状态、业务状态、重试规则或错误判定逻辑。
- 前端自己拥有的输入校验、按钮说明、成功提示、空状态和加载状态仍进入九语言词典。

### 5.3 不属于后台功能修改的工作

- Next.js 服务端渲染的多语言 metadata。
- 官网语言 URL、重写、跳转和 sitemap。
- 设置或读取 `score_locale` Cookie。
- 浏览器端日期、数字、货币和状态标签格式化。
- 本地化截图生成脚本。

## 6. 用户故事

1. 作为首次访问者，我希望选择自己的语言，并在后续访问中保留选择。
2. 作为中文用户，我希望主页介绍和产品截图都显示中文，而不是外层中文、截图英文。
3. 作为日语或韩语用户，我希望导航、表单和前端状态使用同一种语言，并接受后台或接口错误继续显示英文。
4. 作为欧洲语言用户，我希望较长翻译不会挤压按钮、遮挡谱面或变成四五行标题。
5. 作为乐谱用户，我希望切换语言只改变界面文字，不改变乐谱、音符、版本、播放和导出结果。
6. 作为搜索访问者，我希望从搜索结果进入对应语言页面，而不是进入后再依赖 Cookie 切换。

## 7. 信息架构与技术方案

### 7.1 Locale 配置

建立唯一语言配置源，每种语言至少包含：

- `code`
- `htmlLang`
- `label`
- `shortLabel`
- `dateLocale`
- `numberLocale`
- `fontGroup`
- `direction`，本项目均为 `ltr`
- 官网 URL 前缀
- 默认回退语言

### 7.2 词典结构

建议建立共享 `packages/i18n`：

```text
packages/i18n/
  src/
    locales.ts
    formatters.ts
    glossary.ts
    messages/
      en/
        common.ts
        homepage.ts
        features.ts
        workspace.ts
        billing.ts
        support.ts
      zh-CN/
      zh-TW/
      ja/
      ko/
      fr/
      es/
      de/
      ru/
```

要求：

- 英语作为键结构和缺失翻译回退基线。
- 构建或测试时验证各语言键集合一致。
- 页面不再直接编写多层语言三元表达式。
- 支持变量插值、复数和格式化，不通过字符串拼接组织句子。
- 只把当前页面、当前语言需要的词典发送到浏览器。

### 7.3 语言 URL 与持久化

官网：

- 英语保留当前 URL，避免破坏既有链接。
- 非英语使用 `/zh-cn`、`/zh-tw`、`/ja`、`/ko`、`/fr`、`/es`、`/de`、`/ru`。
- 切换语言时尽量保持当前页面语义，例如 `/score-editor` 切到 `/de/score-editor`。
- 无对应语言页面时回退同一页面英语版，不静默跳回首页。

产品工作台：

- 使用共享 `score_locale` Cookie。
- 从官网进入产品端时继承当前语言。
- 产品端切换语言不离开当前工程、不重建版本、不丢失未提交表单状态。

### 7.4 技术词汇规则

默认保留：

- ScoreTransposer
- MusicXML
- MIDI
- OMR
- PDF / PNG / SVG / WAV / MP3
- Score JSON
- BPM
- Tone.js
- Audiveris

“简谱 / Jianpu / numbered notation”、移调、调号、拍号、谱号、声部等建立九语言术语表，并由人工审核决定页面显示形式。

枚举值、API 字段、文件扩展名和数据结构不得翻译，只翻译展示标签。

## 8. 功能需求

### 8.1 语言选择

- `I18N-FR-001`：全局语言选择器显示九种语言本名。
- `I18N-FR-002`：选择后立即保存 Cookie 并刷新当前页面语言。
- `I18N-FR-003`：官网和产品端使用同一语言选择。
- `I18N-FR-004`：键盘和屏幕阅读器可完整操作语言选择器。
- `I18N-FR-005`：移动端语言选择器不得挤压主 CTA。

### 8.2 官网

- `I18N-FR-010`：首页所有导航、标题、正文、按钮、筛选项、FAQ 和状态可翻译。
- `I18N-FR-011`：所有产品功能介绍页使用当前语言。
- `I18N-FR-012`：About、Support、Pricing、Privacy、Terms 及普通用户可见公共页面使用当前语言。
- `I18N-FR-013`：metadata、Open Graph、结构化数据和可访问名称使用当前语言。
- `I18N-FR-014`：链接切换语言后保持相同功能意图。

### 8.3 产品工作台

- `I18N-FR-020`：登录、注册、激活、账户和账单界面可翻译。
- `I18N-FR-021`：上传和免费单页预览界面可翻译。
- `I18N-FR-022`：OMR 诊断、候选审阅和状态可翻译。
- `I18N-FR-023`：图形编辑器、音高、时值、声部和版本操作可翻译。
- `I18N-FR-024`：简谱、移调、播放、循环、节拍器和导出界面可翻译。
- `I18N-FR-025`：后台和接口错误保持英文；前端自有校验、空状态、加载状态和成功提示可翻译。
- `I18N-FR-026`：切换语言不改变任何工程数据和业务状态。

### 8.4 产品截图

- `I18N-FR-030`：每个语言拥有对应的真实产品截图映射。
- `I18N-FR-031`：截图必须来自真实运行产品，不后期替换文字。
- `I18N-FR-032`：10 张功能图新增 8 个非英语版本，共约 80 张新截图。
- `I18N-FR-033`：首页只请求当前语言图片。
- `I18N-FR-034`：截图语言、页面语言和替代文本保持一致。

## 9. 前端适配规则

### 9.1 长文案

- 德语、俄语、法语和西班牙语按照比英语更长的文本进行设计。
- Flex/Grid 子元素默认具备 `min-width: 0`。
- 按钮允许合理增加宽度或高度，不压缩为不可读文本。
- 对不可避免的长单词使用安全断词，但不得随意拆分品牌和格式名。
- 桌面核心标题目标为 1～2 行；移动端允许自然增加，但不得逐词堆叠。

### 9.2 字体

- 英语、法语、西班牙语和德语使用同一拉丁字体组。
- 俄语字体组必须完整支持西里尔字符。
- 简体中文、繁体中文、日语、韩语使用各自合理的系统或 Noto 字体回退。
- 不得在所有语言页面一次性下载全部 CJK 字体。
- 乐谱符号和 OSMD/VexFlow 渲染字体不随 UI 语言替换。

### 9.3 乐谱界面

- 五线谱、音符、简谱数据、播放光标和小节位置不因语言切换改变。
- UI 标签可以翻译，乐谱画布比例和方向保持一致。
- 产品截图中的真实谱面必须使用同一测试工程，便于跨语言比对。

## 10. 多语言 SEO

- 每个公开语言页面设置正确的 `<html lang>`。
- 每个页面声明九语言 `hreflang` 与 `x-default`。
- canonical 指向当前语言的规范 URL。
- sitemap 包含所有可索引语言版本及相互替代关系。
- 页面标题、描述、Open Graph 和 JSON-LD 使用对应语言。
- 不以 Cookie 作为搜索引擎发现非英语页面的唯一方式。
- 产品工作台登录后页面不为多语言 SEO 建立索引副本。

## 11. 性能与可访问性

- 当前语言词典按需加载，不把九套词典全部打进首页客户端包。
- 图片预算按“单语言页面实际请求”验收，同时限制仓库总素材规模。
- 语言选择器具备正确 label、焦点、展开和选择状态。
- 表单 label、前端自有校验状态、`aria-live` 和替代文本可翻译；接口错误内容保持英文。
- 高对比、减少动态和强制颜色模式继续有效。
- 切换语言后焦点和页面标题应合理更新。

预计：3～4 个工作日。

- 首页及全局 Chrome 九语言化。
- 功能介绍页九语言化。
- 公共用户页面九语言化。
- 语言 URL 和跨语言页面映射。

阶段门槛：九语言官网页面可访问，无阻塞性英文残留和横向溢出。

### I18N-P2：产品工作台核心路径

### I18N-P3：真实产品截图

阶段门槛：页面、截图、可访问文本语言 100% 一致；仅请求当前语言图片。

### I18N-P4：次级用户闭环

预计：3～5 个工作日。

交付：

- 账单、支付结果、续费和退款状态。
- 教学、分享、学生和支持页面。
- 激活、找回密码、版权投诉等普通用户路径。

阶段门槛：普通用户可触达页面全部进入九语言覆盖清单。

### I18N-P5：SEO、性能与最终 QA

预计：4～6 个工作日。

交付：

- `hreflang`、canonical、多语言 sitemap 和 metadata。
- 字体和按需词典优化。
- 九语言浏览器矩阵和截图基线。
- staging 验收报告及 production 发布清单。

阶段门槛：全部成功指标和 Definition of Done 通过后，才允许提出 production 发布申请。

## 13. 上线批次

1. 第一批：英语、简体中文、繁体中文。
2. 第二批：日语、韩语。
3. 第三批：法语、西班牙语、德语、俄语。

所有批次先进入 staging。某一批次未通过时，不影响前一批继续在 staging 验证，但不得提前进入 production。

## 14. 测试与验收矩阵

每种语言至少覆盖：

- 首页。
- 一个功能介绍页。
- 登录/注册。
- 上传。
- 工程库。
- OMR 候选审阅。
- 编辑器。
- 简谱或移调。
- 播放。
- 导出。
- 账单/支持。

每个关键页面至少覆盖：

- 390px。
- 768px。
- 1280px。
- 1920px。
- 必要时 2560px 超宽屏。

自动检查：

- 缺少和多余词典键。
- 非预期英文文本。
- 横向溢出。
- 图片语言和替代文本不匹配。
- 错误覆盖层与控制台错误。
- 语言 Cookie 和跨域持久化。
- metadata、canonical 和 `hreflang`。
- 首页资源预算。

人工检查：

- 音乐术语正确。
- 营销文案自然。
- 法律和支付说明不产生错误承诺。
- 德语、俄语长文案不破坏层级。
- CJK 字体、标点和行高自然。

## 15. 翻译与内容治理

1. 英语作为源文案基线，但不要求逐字直译。
2. 机器翻译只能作为初稿，不能直接作为 production 批准依据。
3. 术语表先于页面翻译完成。
4. 法律、隐私、支付和版权内容需专业人工审核。
5. 每条翻译记录语言、翻译人/来源、审核人、更新时间和内容版本。
6. 源文案变更后，对应翻译自动标记为需要复核。
7. 未审核语言只能进入 staging，不得出现在 production 语言选择器。

## 16. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 继续新增语言三元判断 | 词典架构完成前不添加第三种语言页面 |
| 图片语言与页面不一致 | 统一截图注册表和自动匹配测试 |
| 德语/俄语撑破布局 | 长文本压力测试和多断点浏览器验收 |
| CJK 字体导致体积上升 | 按语言加载字体或使用系统字体回退 |
| 不同语言页面出现英文接口错误 | 这是已确认产品边界；保持接口原文，不修改后台或接口契约 |
| 翻译改变业务含义 | API 枚举和数据不翻译，术语表与人工审核 |
| 多语言 SEO 重复内容 | 独立 URL、canonical、`hreflang`、sitemap |
| 素材库从约 630KB 扩大 | 页面只加载当前语言；预算按单语言和仓库总量双重检查 |

## 17. 工期与资源

- 前端架构和页面适配：约 4～6 周。
- 完整语言审核与最终验收：约 1 周，可与开发并行。
- 建议至少安排一名前端负责人、一名内容/本地化负责人，以及对应语言审核资源。
- 管理员后台、邮件和第三方平台本地化如纳入范围，需要重新评估工期。

## 18. Definition of Done

只有同时满足以下条件，九语言前端改造才算完成：

1. 九种语言均存在完整、已审核的关键路径词典。
2. 官网、功能页、产品核心路径和普通用户次级页面全部通过覆盖清单。
3. 约 80 张新增产品图由真实工作区自动截取并正确映射。
4. 九语言所有目标断点无横向溢出、遮挡和错误覆盖层。
5. 乐谱、Score JSON、MusicXML、版本、任务、导出和权限回归测试通过。
6. 多语言 SEO、字体、按需加载和性能预算通过。
7. 后台业务逻辑和接口契约均未被国际化改造改变；后台与接口错误继续保持英文。
8. staging 完成用户验收，且用户明确批准后，才可部署 production。

## 19. 决策记录

- 本期确定支持九种语言，不包含阿拉伯语。
- 英语保留当前官网 URL，其他语言使用可索引前缀。
- 产品工作台使用共享 Cookie 保存语言。
- 真实产品截图按语言生成，不对 PNG 后期改字。
- 本项目定位为前端国际化，不修改后台业务能力。
- 后台报错、API 报错和前端收到的接口英文错误不翻译，保持英文原文。
- 管理员后台和通知渠道不作为首期 production 阻塞项。
